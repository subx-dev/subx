# subx — معرض أعمال وتطبيقات عربي تفاعلي

موقع Portfolio / App Showcase بتصميم داكن وبنفسجي مستوحى من شعار **subx >_**. الواجهة بالكامل تدعم اللغة العربية واتجاه RTL، وتتضمن خلفية Three.js متحركة، مؤثرات GSAP عند التمرير، بطاقات تطبيقات قابلة للتصفية، وتجربة متجاوبة للجوال.

## الملفات

```text
subx-portfolio/
├── index.html                # هيكل الموقع، الـ SEO، والمكتبات الخارجية
├── style.css                 # الهوية البصرية، الحركة، وتجاوب الجوال
├── main.js                   # WebGL والتفاعلات وتحديث التطبيقات آليًا
├── update/
│   └── apps.json             # عدّل هذا الملف لإضافة أو إزالة مشاريعك
├── assets/
│   ├── subx-original.jpg     # صورة الشعار الأصلية المرفقة
│   ├── subx-symbol.png       # العلامة المستخرجة بخلفية شفافة تقريبًا
│   ├── subx-lockup.png       # الشعار الكامل
│   └── favicon.png           # أيقونة تبويب الموقع
├── .nojekyll
└── README.md
```

## كيفية إضافة تطبيق جديد

افتح `update/apps.json` وأضف عنصرًا إلى المصفوفة `apps`:

```json
{
  "id": "myapp",
  "name": "تطبيقي",
  "latinName": "MY APP",
  "description": "وصف عربي قصير للتطبيق وفائدته.",
  "icon": "✦",
  "category": "android",
  "platform": "تطبيق أندرويد",
  "status": "متاح للتحميل",
  "tags": ["KOTLIN", "ANDROID", "PRODUCTIVITY"],
  "accent": "#9b51e0",
  "featured": false,
  "links": [{ "label": "تحميل التطبيق", "url": "https://github.com/USERNAME/REPO/releases/latest" }]
}
```

- **icon**: يمكن أن يكون رمزًا نصيًا أو مسار صورة نسبيًا مثل `update/icons/myapp.png`. ضع الصورة داخل `update/icons/` عند استخدامها.
- **category**: أحد الخيارات: `android` أو `web` أو `tools`.
- **links**: `url` قد يكون رابطًا كاملًا `https://...` أو مسارًا نسبيًا مثل `update/files/myapp.apk`. إذا تركته فارغًا، يظهر الزر «قريبًا» بدل رابط معطّل.
- **accent**: لون البطاقة بصيغة HEX مؤلفة من ست خانات.
- **featured**: بطاقة بارزة أعرض من غيرها في الصف الأول. يُفضَّل تعيينه على مشروع واحد فقط.
- بعد التعديل، **احفظ وارفع فقط الملفات المتغيرة داخل `update/`**. ستنعكس التغييرات عند تحميل الصفحة/تحديثها، دون تعديل `index.html` أو `main.js`.
- السجلات الأربعة الحالية **أمثلة توضيحية**؛ استبدلها بمشاريعك وروابطها الحقيقية قبل النشر العام.

## مهم: تفعيل التواصل

افتح `main.js` في أعلى الملف وعدّل البريد:

```javascript
const SITE_CONFIG = Object.freeze({
  email: 'your-real-email@example.com',
  projectFile: 'update/apps.json'
});
```

البريد في النسخة التجريبية Placeholder عمدًا؛ سيعرض زر التواصل تنبيهًا حتى تستبدله ببريدك الحقيقي، كي لا يحوّل الزوار إلى عنوان غير تابع لك.

## تشغيل الموقع محليًا على Windows / Linux / macOS

لا يكفي فتح `index.html` بالنقر المزدوج: معظم المتصفحات تمنع `fetch('update/apps.json')` عند العمل عبر `file://` لأسباب أمنية.

افتح Terminal/PowerShell من **داخل مجلد المشروع** وشغّل:

```bash
python -m http.server 8000
```

ثم افتح `http://localhost:8000` في المتصفح. أو استخدم إضافة **Live Server** داخل VS Code. يحتاج تحميل الخطوط وThree.js وGSAP إلى اتصال بالإنترنت لأن الملفات تُحمَّل من CDN. عند غياب المكتبات يبقى المحتوى الأساسي والتصفية متاحين بدون مؤثرات 3D.

## النشر على GitHub Pages

1. أنشئ مستودع GitHub جديدًا، مثل `subx-portfolio`.
2. ارفع **محتويات المجلد** إلى جذر المستودع، لا المجلد الخارجي نفسه (أي يجب أن يكون `index.html` في الجذر).
3. انتقل إلى **Settings → Pages → Build and deployment**.
4. اختر **Deploy from a branch**، وحدد الفرع `main` والمجلد `/(root)`، ثم اضغط Save.
5. بعد اكتمال النشر، افتح رابط الموقع الذي تعرضه صفحة Pages (عادة من شكل `https://USERNAME.github.io/subx-portfolio/`).
6. لتحديث التطبيقات مستقبلًا: غيّر `update/apps.json` وأضف الصور أو الملفات اللازمة داخل `update/`، ثم ارفع التعديلات فقط.

> روابط الملفات في الموقع **نسبية** وليست مطلقة؛ لذا تعمل في GitHub Pages حتى عندما يكون المشروع مستضافًا في مسار فرعي `/subx-portfolio/`.

## الاستجابة والأداء

- الخلفية تراقب موضع التمرير وتغيّر موضع المجسم ومظهر الأمواج مع كل قسم، وتتفاعل مع المؤشر والنقرات.
- للأجهزة الصغيرة تخفّض كثافة الجسيمات ودقة WebGL.
- إعداد النظام `prefers-reduced-motion` يعطّل الحركة المكثّفة احترامًا لإمكانية الوصول.
- النصوص والتطبيقات تظل ظاهرة حتى إذا لم تدعم البطاقة الرسومية WebGL.
- رفع ملفات APK كبيرة عبر GitHub Releases وربط الرابط في `apps.json` غالبًا أسهل من تضمينها في المستودع.

## ملاحظات تقنية

- Vanilla HTML/CSS/JavaScript؛ لا يحتاج `npm install` أو build step.
- Three.js (r128 UMD) وGSAP (3.12.5) عبر CDN، والخط IBM Plex Sans Arabic من Google Fonts.
- تستخدم البطاقات `textContent` وتفلتر روابط `javascript:` لأمان أفضل عند تحديث JSON.
- لا يتم استخدام خلفية ثابتة تحبس الصفحة: التمرير طبيعي لكل الأقسام، بينما مؤثرات WebGL تستجيب لحركة التمرير.
